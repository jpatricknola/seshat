# Command Flow

End-to-end path from an MCP tool call to an Ableton state change.

```
Claude Desktop / Claude Code
        │  MCP tool call: set_mixer {"track": 0, "pan": -1.0}
        │  (stdio via `mix mcp`, or streamable HTTP with the app running)
        ▼
Seshat.MCP.Server                       ← components generated by Seshat.MCP.Tools
  → Peri validates params against the generated schema
  → returns atom-keyed params
        ▼
Seshat.Tools.Handlers.call/2            ← normalises keys to strings
  → validates authoritatively against the tool schema
    (`Seshat.Tools.Validation` catches type gaps in Peri)
  → do_call/2 clause per tool name
  → simple tools call Transport directly
  → multi-step tools build a %Command{} and hand it to Registry
        ▼
Seshat.Commands.Registry.execute/1
  → sequences multi-step operations
        ▼
Seshat.OSC.Transport (GenServer)
  → encodes via Seshat.OSC.Message
  → sends UDP to port 11000
  → awaits query replies on 11001
  → broadcasts inbound messages on the "osc:in" PubSub topic
        ▼
AbletonOSC (Python MIDI Remote Script) → Ableton Live
        │
        ▼
Seshat.Session.State
  → maintains the in-memory mirror from listener pushes
  → coalesces refreshes after structural changes
```

`Handlers` is the protocol-neutral seam. A future integration can call it
directly without changing the OSC layer, but MCP is the only model-facing entry
point maintained by Seshat.

## Failure modes to know

- **Wrong OSC address** — silent. Always check
  [priv/AbletonOSC/API.md](../../priv/AbletonOSC/API.md).
- **Ableton not running** — queries time out; sends cannot detect the absence.
- **Port 11001 in use** — a second Seshat can send but cannot receive replies.
- **Atom vs string keys** — normalized in `Handlers.call/2`.
- **Invalid MCP params** — `Seshat.MCP.Server` rewrites known-tool Peri
  rejections into model-readable tool results; `Validation` remains the
  authoritative check before OSC.
